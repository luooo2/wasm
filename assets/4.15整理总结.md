- 解释哪些程序结构导致 Wasm 性能差距最大/最小
    
    - 计算密集度 在控制流规整，热点规模较小的情况下，wasm能生成质量接近native的机器码，native的全局优化收益并不明显；但在较大型的复杂计算中，native 编译器能够更充分地应用向量化、指令调度等优化技术，而 Wasm 经由栈机表示到本机代码的转换路径在优化深度上受到限制，导致机器码质量差异在大量计算中被累积放大。
        
    - 内存访存指令 如果每次内存访存都要进行边界检查，大量的访存指令会拖慢wasm运行效率；但现有运行时都有？对边界检查做优化，所以在 polybenchC 等大型数值计算 kernel 中，内存指令越高的程序反而对缩小wasm与native性能差距有益；解释可以用 roofline模型进行初步解释？ 可以用硬件计数器数据进行验证； 但是在微基准程序的内存的各种操作（包括随机读/写、顺序读/写、跨步读/写、内存分配等）具体的wasm/native差距表现并不一致，需要进一步明确内存访存各个行为的具体影响和表现。
        
    - 系统调用 整体而言系统调用应该是拖慢wasm运行效率的，但具体却又与运行时 api 的实现有关，无法直接定论“系统调用一定让wasm更慢”；

#### 阶段 1：构建静态特征空间 (Feature Engineering)

这是“特征体系”的核心。特征必须在编译期静态提取，且具备明确的语义。

- **操作方法：** 编写一个自定义的 LLVM Analysis Pass，在 LLVM IR 层面扫描程序并输出特征向量。
    
- **关键特征设计：**
    
    - **控制流类：** 基本块平均大小、基本块出度、循环嵌套深度、非结构化跳转模拟比例。
        
    - **数据流与访存类：** Load/Store 指令占比、Phi 节点数量（衡量寄存器分配压力）。
        
    - **Wasm** **特有惩罚类：** 间接调用 (`call_indirect`) 密度、异常处理/类型转换块频率。

#### 阶段 2：基准测试与多维 Label 采集 (Data Collection)

不能只测运行时间。运行时间是宏观结果，底层硬件事件才是解释性能差距的“桥梁”。

- **基准选择：** 必须包含多样化的程序。使用 PolyBench（访存与计算密集，控制流简单）作为 Wasm 表现良好的 Baseline；使用 SPEC CPU（控制流极其复杂）作为 Wasm 表现糟糕的 Baseline。
    
- **Label 采集：** 使用 Linux `perf` 工具（Performance Monitoring Unit, PMU）采集 Native 和 Wasm 运行时的微架构指标：
    
    - Y_1: 指令膨胀率 (Instructions retired)
        
    - Y_2: 分支预测失败率差异 (Branch-misses)
        
    - Y_3: 缓存命中率差异 (L1-dcache-load-misses)
        
    - Y_4: 执行时间鸿沟 (Execution Time Gap)
        

#### 阶段 3：建立因果归因与可解释模型 (Interpretable Modeling)

将阶段 1 的静态特征 X 与阶段 2 的性能 Label Y 进行拟合。

- **摒弃黑盒：** 不要使用深度神经网络（DNN）。
    
- **推荐方法 1（****广义线性模型** **GLM** **+** **L1 正则化****）：** 使用 Lasso 回归筛选出对 Wasm 性能劣势贡献最大的核心结构特征。模型可以直接输出数学表达式，例如：“基本块平均大小每减少 10 条指令，Wasm 的分支预测惩罚增加 X\%”。
    
- **推荐方法 2（基于****树模型****的 SHAP 值）：** 训练一个随机森林或 XGBoost 模型预测性能差距，然后使用 SHAP (Shapley Additive exPlanations) 框架输出特征重要性图表，直观解释哪些程序结构是导致某个具体程序 Wasm 性能大幅落后的“罪魁祸首”。

#### 阶段 4：定义边界与结论输出

基于模型结果，系统性地回答：

1. 哪类代码（如：包含大量密集小循环和虚函数调用的 C++ 代码）**绝对不适合**编译为 Wasm？
    
2. 在什么边界条件下（如：纯顺序数组计算且消除边界检查），Wasm 可以实现 **90% 以上接近甚至超越** Native 性能？ （即探讨 wasm 性能接近 native 的边界条件）
    
3. 对结构性特征导致的性能差距，基于 wasm 底层设计给出原因和解释（可以+case study，一些异常程序（wasm 优于 native）的解释说明）
    
4. 能够针对任意给定程序，说明其哪些结构特征会导致性能差距？
