
**研究主题**：
在给定编译链与执行环境下，程序的静态结构特征是否能够解释并预测其在 WebAssembly 与 native 之间的相对性能趋势？

**研究边界**：
- 语言：`C`
- native 编译器：`clang`
- wasm 编译器：`wasi-sdk clang`
- wasm runtime：`wasmtime`
- 平台：host computer
- 优化级别：主用 `-O2`
- 指标：执行时间


**标签定义**：
根据性能指标 r = T_{wasm} / T_{native} 
可设：
- \( r > 1.10 \) → `native-better`
- \( 0.90 \le r \le 1.10 \) → `similar`
- \( r < 0.90 \) → `wasm-better`
阈值可以后面做敏感性分析，例如 5%、10%、15%。

**特征设计**：
- Compute density 算术/逻辑指令数 / 总指令数
- Memory access density `load + store` / 总指令数
- Syscall / host-call density 识别系统调用白名单
方便的可以使用LLVM IR提取，不方便的可以使用wasm字节码提取（wasmparser工具）；
系统调用密度可以先限定明确系统调用白名单，然后进行统计，或者干脆拆分成更多小特征，如 `import_fd_function_count` 等特征。可适当参考论文中特征设计。

产出：
- 特征设计表（含定义等）
- 特征提取脚本/程序（host为windows 11，也可使用linux后续使用虚拟机）
