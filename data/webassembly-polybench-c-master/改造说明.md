# 改造说明：适配 WASM/WASI 的 PolyBench/C

## 背景
在使用开源 `webassembly-polybench-c-master` 的 `utilities/polybench.c` 内部计时器（编译时开启 `-DPOLYBENCH_TIME`）时，针对 WASM/WASI 目标编译出现错误：

- `call to undeclared function 'gettimeofday'`

该错误说明：当前 wasi-sdk sysroot 下，`gettimeofday()` 不可用（至少在头文件与声明层面不提供）。

## 本次改造
### 1) 修改文件：`utilities/polybench.c`
定位到 `rtclock()` 函数中的时间实现逻辑。

将原本面向 `POLYBENCH_TIME` 的实现：
- 使用 `gettimeofday()` 获取当前时间

替换为：当目标为 WASI（`__wasi__` 定义）时，改用
- `clock_gettime(CLOCK_MONOTONIC, ...)`

从而：
1. 消除 `gettimeofday` 未声明导致的编译失败；
2. 保证在 WASI 运行时同样可以获得单调时钟，满足计时需求；
3. native 与 wasm 仍可复用 PolyBench 的计时打印路径（本改造不改变输出格式的总体“单行数值”特征）。

### 2) 结果解析配套改造：`src/run_polybench.py`
（此处属于本项目的脚本侧适配，不在 polybench 上游仓库内）

PolyBench 在不同计时路径下通常会输出“只包含一个数字的单独一行”。因此脚本侧做了增强解析：
- 优先匹配带标签的时间格式；
- 兜底匹配输出中最后一行“numeric-only token”；
- 若 token 含小数按 seconds->ms 转换；
- 若 token 为整数按 microseconds->ms 转换。

并且你的“label_by_ratio 只使用内部计时”的要求继续成立：ratio/label 均基于解析到的 `POLYBENCH_TIME` 内部计时中位数计算。

## 你可以复现的流水线
1. 运行 `src/build_polybench.py` 完成 native/wasm 产物编译；
2. 运行 `src/run_polybench.py` 跑全套 30 个 kernel；
3. 查看 `data/results/` 下输出的：
   - `polybench_summary.csv`
   - `polybench_raw.csv`
   - `polybench_internal.csv`

## 备注
- 本次适配是最小侵入式：在 `polybench.c` 中仅对 WASI 编译目标更换计时实现，避免引入对运行时 API 的额外依赖。
